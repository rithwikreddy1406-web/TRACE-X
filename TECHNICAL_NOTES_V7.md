# TRACE-X v7 technical notes — dataset-specific offline analysis

**Architecture:** browser (same-origin static frontend) → Python standard-library HTTP API bound to loopback → dataset-scoped processing thread → atomic dataset activation → new dashboard and UTXO JSON. External APIs, CDNs and remote model inference are not used. Dependencies (`scikit-learn`, `numpy`, `joblib` and transitive scientific packages) must be locally installed before the offline run.

**Ingestion:** CSV and JSON arrays/objects or XML transaction entries → strict canonical input/output lists, UTC timestamps, optional P2P observations, optional explicit previous outpoints. The source SHA-256 is recorded; validation errors reject the batch and preserve the previous active investigation. A single process accepts one processing job at a time. This is a developer prototype, not a multi-user queue service.

**Graph and clustering:** common-input-address union-find creates tentative ownership clusters; no merges based only on IP. A directed, aggregate entity graph is generated for exploratory visualization using input/output co-occurrence. Its apparent transferred amounts can overcount for multiple input clusters; do not treat this as audited provenance. Network associations are only exported when provided. Explicit spend references are audited separately using the v6 audit module.

**Detection:** unsupervised Isolation Forest for ≥50 transactions, with an additional MLP reconstruction model for ≥100. Features include input/output cardinality, BTC volume transforms, output concentration/variation, fee, input wallet frequency, self-output indicator, and an availability flag for source IP. Models are fitted to the uploaded batch (not a trusted benign reference). Scores are normalized to batch quantiles. The largest reconstruction residuals are exported as descriptive **feature deviations**, not SHAP values or independent causal explanations. Below 50 transactions, ML is marked unavailable, all anomaly scores are zero and only available structural evidence is ranked.

**Scoring:** composite = 0.40 × normalized structural evidence + 0.20 × relative maximum transaction anomaly. Independent seed-propagation and network-risk weights are disabled for imported datasets. A HIGH/CRITICAL UI tag is an adjustable triage threshold, not an independently calibrated confidence, verified illicit classification or a finding of guilt. The system does not use synthetic `ground_truth_entities.csv` during new-data scoring.

**Data lifecycle:** `data/v7_datasets/ds_<uuid>/source/<original filename>` plus a manifest and `results/`. An active pointer is atomically replaced only after successful export. The browser loads `/api/data` and `/api/utxo` using that pointer. Dataset IDs prevent accidental cross-dataset graph, alert and UTXO evidence joins; browser cases carry a dataset-specific snapshot identifier.

**Validation gaps:** real Bitcoin provenance requires complete and authentic previous-output data; production origin correlation requires collection methodology and uncertainty quantification; external benign baselines and held-out labeled data are needed to benchmark ML; large graph scalability, production authentication, long-term tamper-evident audit trail and fully air-gapped dependency packaging require further engineering.
